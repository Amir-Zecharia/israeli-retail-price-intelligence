
## Fixed pilot ingestion

`config/pilot_v1.json` defines the immutable `irpi_pilot` version 1 panel and sealed basket: eleven packaged GTINs, two categories, one source branch per chain, quantity one package per product. It is a convenience engineering pilot dominated by confectionery, not representative of national chains, branches or consumer spending. The implementing assistant reviewed the original paired names, GTIN/check digit, package quantities and units in the genuine October 24 proof. Ambiguous products (for example 21g source metadata versus a 30g name) are excluded. Names may be abbreviated, so this review is limited to published metadata and is not physical package verification. Further categories and branches require a new version and documented review.

Branch IDs deliberately identify the XML source namespace. Shufersal XML034 maps to filename034, Carrefour XML134 maps to filename416. These are observed source partition mappings, not verified geographic branch metadata: city/address remain NULL. Daily discovery filters that fixed filename partition before choosing its latest supported full file, then verifies the XML chain/store IDs. A partition identity change fails collection rather than silently replacing the sample. Listings are bounded to one page each; if the fixed store is absent collection is marked partial/failed. Signed URLs are never retained; provenance keeps public listing URL, exact filename, SHA256, collection timestamp and source update instants. Collection uses UTC; snapshot date uses Asia/Jerusalem. Source update time is the publisher's reported last update, not historical IRPI collection.

Pipeline: `python -m pipeline.ingest`. Network responses use the verified bounded adapter: two attempts on network failures, 30-second timeouts, terminal 403/429, 32MiB compressed/decompressed limits. Eleven selected identities are validated for finite strictly positive prices, exact package quantity/unit, GTIN and names. Counters describe selected-panel records only; full-feed parse rejections are separately recorded and prevent complete publication. Off-panel rows are ignored. Identical duplicates count once; conflicting duplicates reject the entire identity. Missing products are missing coverage, never zero and never substituted.

Runs are serialized using a PostgreSQL advisory lock. Each attempt creates an immutable revision. Source files, observations, raw-to-canonical product mappings, issue details, reconciled counters and terminal status are committed in one transaction. Only complete source partitions and no malformed selected records can publish. `daily_publications` atomically selects one complete revision per sample/day; reruns replace that pointer while preserving old revision observations. Failed and partial attempts cannot replace a published complete day. A database write failure rolls back all new observations, then records a failed run with zero accepted rows and a sanitized error class. A process killed before terminal status remains visibly `started` until the next attempt obtains the exclusive lock and marks that sample's interrupted runs `abandoned`; it never publishes incomplete rows. No backdated observation dates can be supplied through the CLI.

Daily GitHub Actions is prepared at `.github/workflows/daily_ingestion.yml`, scheduled at 07:15 UTC with manual recovery and concurrency control. It requires a pre-migrated database and `INGESTION_DATABASE_URL` secret using the ingestor role. Hosted network access remains unverified; no cloud run or scheduled success is claimed. Re-run the command for the actual collection date; source-update dates must never be used to manufacture past observations.
